Это репозиторий клиента, созданный из ядра CMS (remote `upstream`). Корневой `CLAUDE.md` описывает
ядро: архитектуру, контракт темы и правила кода — они действуют и здесь. Раздел «План миграции» в нём
относится к ядру, здесь его не ведём.

## Главное правило: дизайн только в `src/theme/`

- Код вне `src/theme/` не меняется. Он приходит из ядра слиянием тега (`docs/CLIENT.md`), и любая
  правка в нём будет конфликтовать при каждом обновлении.
- Исключения — файлы, которые генерирует ядро: `docs/BLOCKS.md` (`pnpm blocks:catalog`).
- Если теме чего-то не хватает (новое поле в контракте, новый вид поля в блоке, новая настройка
  ядра, исправление в ядре), не обходи это в теме и не правь ядро здесь: опиши, что нужно, — это
  доработка ядра в репозитории `<ссылка на ядро>`, сюда она придёт с обновлением.
- Свой тип блока — в `src/theme/blocks/index.ts` (`THEME_BLOCKS`), только если в каталоге
  (`docs/BLOCKS.md`) нет ничего похожего и вариант оформления (`BLOCK_VARIANTS`) не подходит.
  Его схема меняется только совместимо, как у блоков ядра.

## Как работаем

- Натянуть макет или его часть — skill `apply-design` (`.claude/skills/apply-design/`).
- Проверка темы: `pnpm lint && pnpm typecheck && pnpm test`, затем `pnpm build && pnpm test:e2e`
  и `pnpm theme:screenshots` — скриншоты блоков из `/_blocks` и страниц сравнить с макетом.
- Обновление ядра — по `docs/CLIENT.md`, раздел «Обновить ядро».
