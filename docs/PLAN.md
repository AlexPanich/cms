# План переписывания CMS

Переписываем самописную CMS с Laravel 5.2 / PHP 5.5 (2016 год, `legacy/`) на TypeScript.

## Принятые решения

| Вопрос             | Решение                                                                    |
| ------------------ | -------------------------------------------------------------------------- |
| Подход             | Своя CMS на Next.js (путь A), а не готовый движок вроде Payload            |
| Данные             | База новая, из старой версии ничего не переносим                           |
| URL и дизайн       | Новые: старые адреса сохранять не нужно, вёрстку и тему OneUI не переносим |
| База данных        | PostgreSQL                                                                 |
| Деплой             | Docker (Docker Compose)                                                    |
| Сообщения коммитов | Conventional Commits, описание на русском (подробно в `CLAUDE.md`)         |

## Стек

- **Next.js** (App Router): SSR публичного сайта и админка в одном приложении.
- **TypeScript** (strict) и **zod** для валидации любого ввода.
- **PostgreSQL** и **Drizzle ORM**.
- **Better Auth** для входа: сессии, регистрация закрыта.
- **shadcn/ui, Tailwind, TanStack Table** для админки, **dnd-kit** для сортировки дерева, меню и галерей.
- **TipTap** как редактор. Он заменяет TinyMCE, CKEditor и Summernote. Виджеты становятся узлами редактора, а не шорткодами.
- **sharp** для миниатюр. Файлы хранятся в томе `storage`, загрузка обычным multipart.
- **Vitest и Playwright** для тестов, **GitHub Actions** для CI.

## Что было в старой CMS

Модули, которые нужно реализовать заново:

- **Страницы**: дерево через `parent_id`, полный путь `full_url` пересчитывается у потомков, у каждой страницы шаблон, SEO-поля, флаг видимости.
- **Меню**: связь меню и страниц с сортировкой, верхнее меню из корневых страниц, подсветка активного пункта.
- **Шаблоны**: страница выбирает лейаут.
- **Тексты**: именованные блоки (`@text(alias)`), которые вставляются в шаблоны.
- **Статьи** с превью-картинкой.
- **Галереи**: загрузка изображений, сортировка, миниатюры, вставка в контент.
- **Документы**: загрузка файлов и список.
- **Пользователи, роли и права**: `view_dashboard`, `edit_pages`, `edit_menus`, `edit_galleries`, `edit_users`, `edit_roles`, `edit_templates`, `edit_documents`, `edit_texts`, `edit_articles`, `edit_from_front`.
- **Редактирование на сайте**: заголовки, контент и тексты правятся прямо на странице.
- **Поиск** по страницам.

## Дыры старого кода, которые нельзя повторить

1. **Выполнение кода через загрузку.** Документы сохранялись в `public/documents` с именем от пользователя и без проверки расширения.
2. **SQL-инъекция в поиске.** Запрос склеивался из строк (`legacy/app/Modules/Search.php`).
3. **Классы по имени из запроса.** `FrontEditController` и `ReplaceWidget` создавали классы по строке из запроса или контента, а `simpleEdit` записывал любые поля модели.
4. **Права не проверялись.** Проверялось только `view_dashboard`, права `edit_*` нигде не использовались.
5. **Удаление через GET** без CSRF-защиты, открытая регистрация, админ из сида с паролем `123456`.
6. **Ошибки в логике:** при удалении страницы её потомки оставались без родителя, при удалении галереи оставались записи изображений, пути пересчитывались без транзакции.

## Этапы

### 1. Каркас ✅

- Next.js 16, TypeScript strict, ESLint, Prettier, Vitest.
- Drizzle, PostgreSQL, мигратор, `/api/health`.
- `Dockerfile` (standalone, приложение не от root) и `docker-compose.yml` (`db`, `migrate`, `app`).
- CI: форматирование, линтер, типы, тесты, миграции, сборка.

### 2. Схема БД ✅

- `pages`: FK `parent_id` (`NULL` для корня, `ON DELETE NO ACTION` — страницу с потомками удалить нельзя), `slug` (CHECK `[a-z0-9-]`), уникальный `path`, `sort`, `menu_title`, `meta_description`, `content` (JSON TipTap), `template`, `published`, `is_home` (частичный уникальный индекс — главная одна).
- Логика дерева в `src/server/pages/`: при смене slug или родителя пути поддерева пересчитываются в одной транзакции (`starts_with`), защита от циклов, перенос ставит страницу в конец нового уровня, порядок соседей меняется только полным списком.
- `menus` (`key`: `main`, `footer`) и `menu_items`: пункт ссылается либо на страницу, либо на URL (CHECK), сортировка.
- `media`: изображения и документы в одной таблице (`kind`), имя файла в хранилище генерирует сервер. Отдельной таблицы документов нет.
- `galleries` (`key` для вставки в контент) и `gallery_items` с сортировкой.
- `texts` (уникальный `key`) и `articles` (`slug`, превью ссылается на `media`).
- `users` совместима со схемой Better Auth (текстовый `id`); таблицы сессий и аккаунтов добавятся на этапе 3.
- Права — `pgEnum` из констант `src/lib/permissions.ts`, отдельной таблицы нет. Связи `role_permissions` и `user_roles`. Права на шаблоны больше нет (шаблоны в коде), галереи и документы объединены в `edit_media`.
- Сид `pnpm db:seed` идемпотентен: системные роли `admin` (всегда все права) и `editor`, меню `main` и `footer`. В Docker выполняется после миграций.
- Тесты: `slugify`, чистые функции дерева и интеграционные тесты сервиса страниц на настоящем Postgres (каждый тест в откатываемой транзакции).

### 3. Вход и права

- Better Auth: вход по email и паролю, регистрации нет, пользователей создаёт администратор.
- Таблицы Better Auth `sessions`, `accounts`, `verifications` рядом с существующей `users`.
- CLI-команда для создания первого администратора: пароль вводится при запуске и не хранится в коде.
- `can(user, permission)` проверяется в каждом server action и route handler, а не только при входе в админку.
- Middleware закрывает `/admin` для гостей.

### 4. Админка

Модули по порядку:

1. Пользователи и роли.
2. Страницы: дерево с перетаскиванием, форма с SEO-полями.
3. Меню.
4. Тексты.
5. Статьи с превью.
6. Галереи: загрузка нескольких файлов, сортировка, миниатюры через sharp.
7. Документы: белый список расширений, хранение вне `public/`, отдача через обработчик.

Общее для всех модулей: таблицы с пагинацией и поиском, формы на zod, flash-уведомления, подтверждение удаления.

### 5. Публичный сайт

- `app/[[...slug]]/page.tsx` ищет опубликованную страницу по `path`.
- Шаблоны — React-лейауты из явного реестра в коде, дизайн новый.
- Меню с активным пунктом, тексты-блоки, галереи в контенте через реестр виджетов.
- `generateMetadata` для SEO, `sitemap.xml` и `robots.txt`.
- Поиск: полнотекстовый поиск PostgreSQL (`tsvector`, русская конфигурация), только параметризованные запросы.

### 6. Редактирование на сайте

- Клиентский компонент загружается только для пользователей с правом `edit_from_front`.
- Редактировать можно только поля из белого списка: `page.title`, `page.content`, `text.body`.
- Сохранение через server action с проверкой права и zod-схемой.

### 7. Тесты и деплой

- E2E на Playwright: вход, создание страницы, публикация, отображение на сайте, загрузка в галерею.
- Продакшен-конфигурация Docker Compose: секреты через env, тома для БД и файлов, резервные копии `pg_dump`.
- После запуска удалить `legacy/`.

## Оценка

Около 4–5 недель работы одного разработчика. Переноса данных и сохранения URL нет, поэтому работы меньше, чем в первой оценке.
